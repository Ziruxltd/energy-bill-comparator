# v1 plan (electricity)

> Working plan for v1. `docs/roadmap.md` tracks progress; this file holds what each phase creates, what "done" means, and the risks. Update it when a phase changes the plan.

## Context

A public app: the user uploads a Spanish electricity bill PDF, Claude extracts it into `ExtractedBill`, and `packages/core` (pure TS) recalculates the bill under each tariff, cross-checks the extracted total and ranks savings. It's a portfolio piece, so tooling, evals and docs count as much as features.

**Decisions confirmed by user:** structured outputs (`messages.parse` + `zodOutputFormat`) instead of tool use; lefthook; the extra dev dependencies approved; page/size limit via magic bytes + 4 MB + free `countTokens` (no pdf-lib). See ADR 003 and 004.

**Model selection rules (user, 2026-10-15):**

- No dynamic or automatic model switching anywhere in the code.
- Each step reads its model from an env var: `ANTHROPIC_MODEL_DETECTION` and `ANTHROPIC_MODEL_EXTRACTION`. Both are read in **one** file, `packages/extraction/src/config.ts`, which has defaults: `claude-haiku-5-5` for detection and `claude-sonnet-5-5` for extraction. `detect.ts` and `extract.ts` take the model as a parameter (so evals can inject it). Only `config.ts` reads `process.env`.
- No fallback, and no retry on a different (more expensive) model. The SDK's `fallbacks` parameter is **not** used. The one Zod-failure retry in `extract.ts` uses the same model.
- `pnpm evals --model <id>` overrides the extraction model for that run only. It never touches production config. Each report records the model, per-field accuracy and estimated cost per bill (from `response.usage` × a price table in the evals script, with source and date).

Verified facts this plan relies on (checked 2026-10-15; re-check before relying on prices or limits):

- **Claude API:** current models are Opus 5.5 ($4/$20 per MTok), Sonnet 5.5 ($2/$10) and Haiku 5.5 ($0.10/$0.50). Opus 5.5, Sonnet 5.5 and Fable 5.1 **reject forced `tool_choice` (`any`/`tool`) with a 400**. The SDK has `client.messages.parse()` plus `zodOutputFormat()` (`@anthropic-ai/sdk/helpers/zod`), which turns a Zod schema into a constrained output and parses the response back. PDFs go in as base64 `document` blocks (32 MB per request, up to 600 pages). `messages.countTokens` is free.
- **Netlify:** buffered synchronous functions have a **6 MB request/response payload limit**, which can't be raised because they run on Lambda. Lambda base64-encodes binary bodies, so the real PDF limit is about **4.5 MB**. **Native rate limiting** is set in code with `export const config = { rateLimit: { windowLimit, windowSize (≤180 s), aggregateBy: ["ip","domain"] } }`. It works on every plan (2 rules on Free) and returns 429. The default sync timeout is unclear: sources say 10 s, 26 s or 60 s. Phase 6 measures it (see Risks).

## 2. Phase 1 (done, 2026-10-16)

The tooling is in the repo: see the root config files, `docs/decisions/003-*` and `004-*`, and the "Tooling" section of `CLAUDE.md`. Where the result differs from the original plan:

- **TypeScript 6.0.3, not 7.x.** TS 7 is the Go rewrite, and typescript-eslint 8 supports TS below 6.1 only. Revisit when typescript-eslint supports 7.
- **Node 22 (LTS), not 24.** It matches the author's machine. Change `.nvmrc` and `NODE_VERSION` in `netlify.toml` together.
- **pnpm 10.34.7, not 12.** pnpm 12 doesn't start under the corepack bundled with Node 22.
- **`onlyBuiltDependencies`** in `pnpm-workspace.yaml`: pnpm 10 blocks dependency install scripts, so only esbuild, lefthook and netlify-cli are allowed to run them.
- **The function is served at `/api/analyze-bill`** (set in the function's `config`). `pnpm dev` runs `netlify dev --filter @ebc/web` so the CLI doesn't ask which workspace package to run.
- Packages are consumed as TS source (`exports: ./src/index.ts`), with no build step and no project references.
- Optional, not done: a Claude Code `PostToolUse` hook to format files after edits.

## Phase 2 (done, 2026-10-16)

- Decided with the author: `ROUND_HALF_UP` per bill line; confidence as fixed keys per field group; every field nullable except `energyType` (`discounts` is `[]`).
- `ElectricityBill` (the extracted bill schema) moved from phase 3 into phase 2, because the union needs a member to be tested. `ElectricityTariff` stays in phase 3.
- The `ExtractedBill` union lives in `core/src/extracted-bill.ts`, not `shared/schema.ts`: shared would import electricity, which imports shared, an ES module cycle.
- `EnergyCalculator.calculateBill` returns `CalculationResult` (`{ ok: true, breakdown } | { ok: false, missingFields }`), so a bill with null fields produces an explainable result instead of an exception.
- The interface test is checked by `pnpm typecheck` (`expectTypeOf`); Vitest alone doesn't check types.

## 3. Open questions and risks (with recommendations)

| #   | Risk / question                                                                                                                             | Recommendation                                                                                                                                                                                                                                                                                                                                                                                |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1  | **Zod → schema conversion.** Tool use + `zod-to-json-schema` is an extra dependency, and forced tool choice is rejected by Opus/Sonnet 5.5. | Use the SDK's `zodOutputFormat` with `messages.parse` (Zod 4). No extra dependency, and the output is constrained to the schema. Structured outputs support a subset of JSON Schema, so keep the **output schema** plain (objects, strings, nullable, enums). Apply refinements (date order, decimal regex, totals) in a **second, stricter Zod parse** in code. Spike this first in phase 4. |
| R2  | **Payload limit.** 6 MB buffered, and binary is base64 on Lambda, so about 4.5 MB of PDF.                                                   | Hard limit of **4 MB**, checked in the browser (UX) and again in the function (trust boundary). Send the raw `application/pdf` body (`fetch(body: file)`, `req.arrayBuffer()`). No multipart parsing or extra dependency is needed. Bills are typically under 1 MB.                                                                                                                           |
| R3  | **Page limit without a PDF library.**                                                                                                       | Use magic bytes `%PDF-` + size, then a free `countTokens` call with the document block, and reject above about 20k tokens. Tokens are what cost money, so cap tokens directly instead of pages. Decided: no `pdf-lib`.                                                                                                                                                                        |
| R4  | **Function timeout.** It's 10–60 s depending on plan/source, and extraction with a PDF can take 10–30 s.                                    | Measure in phase 6. Mitigations in order: a faster extraction model (an eval trade-off), lower `effort`, streaming the response body (20 MB streamed limit, which keeps the connection alive). Last resort: a background function + polling. Netlify Blobs is not an option because PDFs must never be stored. Don't design for that up front.                                                |
| R5  | **The rate limit is per-window (≤180 s), not per day.**                                                                                     | Combine the native per-IP rule (e.g. 5 requests / 180 s) with the Console monthly spend cap as the hard ceiling. In-memory counters would be wrong: instances don't share memory and cold starts reset them.                                                                                                                                                                                  |
| R6  | **Refusals / stop reasons.**                                                                                                                | Check `stop_reason` (`refusal`, `max_tokens`) before reading output, and map it to a typed error shown to the user. No model fallback, by rule.                                                                                                                                                                                                                                               |
| R7  | **Privacy in errors.** SDK errors and Zod issues can echo extracted values.                                                                 | The function logs only error class, code, token usage and timings. Zod issue _paths_ are allowed, _values_ are not. Tested in phase 6.                                                                                                                                                                                                                                                        |
| R8  | **Detect + extract both send the PDF**, so input tokens double.                                                                             | Acceptable: detection on Haiku 5.5 costs about $0.001 per bill and rejects non-bills before the expensive call. Re-evaluate from eval cost data. Prompt caching doesn't help here because caches are per model.                                                                                                                                                                               |
| R9  | **Tariff prices go stale.**                                                                                                                 | `checkedAt` is shown in the UI disclaimer. A unit test fails if any tariff has a placeholder price or `checkedAt` older than N days. Run it locally before deploy, not in CI, so CI isn't time-dependent.                                                                                                                                                                                     |
| R10 | **Tool versions** (peer ranges between Vite, Vitest, vue-tsc and typescript-eslint).                                                        | Pin exact versions at install time after checking peer dependency ranges (`npm view <pkg> peerDependencies`). Don't trust memory. See section 2 for what this changed in phase 1.                                                                                                                                                                                                             |
